# Roadmap

c2f-rs is a Rust reimplementation of [Cell2Fire-W (C2F-W)](https://github.com/fire2a/C2F-W),
a grid-based forest fire spread simulator. It is not a line-by-line port: we rebuild the
simulator one layer at a time, keep only what is needed, and check every layer against
outputs of the C++ reference before moving on.

## How the simulator works

The landscape is a grid of square cells. When a cell burns:

1. A **fuel model** turns the cell's fuel and the weather into a head rate of spread and
   a fire shape (length-to-breadth ratio).
2. The fire grows as an **ellipse** pushed by the wind, which gives a rate of spread
   towards each of the 8 neighbours.
3. Every time step (1 minute by default) the fire advances towards each neighbour.
   When it reaches a neighbour's centre, that neighbour receives a **message**.
4. A cell that gets a message ignites if its own head rate of spread is above a
   threshold. Otherwise it stays unburnt, and gets a message again next time step.
   A burning cell with nowhere left to spread burns out.
5. The weather changes every 60 minutes. The fire stops when no cell is burning or
   the weather rows run out.

## Simplifications

Compared with C2F-W, the propagation engine:

- keeps one flag per cell ("has fuel and has not caught fire yet") instead of per-cell maps of
  directions that are trimmed as neighbours burn. Both give the same result.
- has no "repeat" codes passed between cells. A fire that sends no message in a period
  simply carries on while some cell is still burning.
- runs a single fire per call. Multi-year runs are dropped.
- reads the rasters directly, without writing `Data.csv` into the input folder.
- numbers cells from 0. C2F-W numbers them from 1 in its files.

## Validation strategy

The C2F-W repository ships reference outputs (`test/target_results.zip`): 113 simulations
for each fuel model, on tiny grids. With default options the only random choice is the
ignition cell, and that is logged, so every simulation can be replayed exactly as a
fixed-ignition run.

- Burn scars, ignition times and messages are compared as sets, because C2F-W writes
  messages in hash-map order.
- Numbers are compared with the precision C2F-W prints (6 significant digits).
- Cases without reference outputs (slope, large grids, crown fire) will need new targets
  generated by building the C++ simulator (Docker, Debian, as in its CI).

Reference data used by the tests lives in `tests/data/` (see the README there).

## Differences from C2F-W

C2F-W is our reference for the model: the fuel model equations, the elliptical spread and
the message-passing propagation. It is not a reference for implementation details. We use
its outputs to validate the model, but we do not copy its artefacts. Each deliberate
difference is listed here, with the reason.

### Wind direction and cell size keep their decimals

C2F-W reads both with `std::stoi`, which drops the decimals: a wind from 157.9° becomes
157°, and a 100.02265625 m cell becomes 100 m.

This comes from the original Cell2Fire, which was built around the Canadian FBP program
(`FBP5.0.h`, B.M. Wotton, 1992). There, wind azimuth, slope, aspect and elevation are whole
numbers, which suits Canadian fire weather records and the FBP tables. Cell2Fire read them
as integers, and its cell size too, since its landscapes were 100 m grids. When C2F-W added
Scott & Burgan and Kitral, wind direction became a decimal number, but it was still parsed
as an integer.

The effect is small on the bundled data: under 1° of wind direction in the Villarrica
weather files, and 0.02% of cell size in Portezuelo. But it grows as cells get smaller: a
12.5 m cell becomes 12 m (4% faster spread), and a cell under 1 m becomes 0 m.

Validation is not affected: the `sb-asc` inputs are whole numbers.

### Time starts at ignition, and weather changes on the hour

In c2f-rs, time starts at 0 when the fire ignites, and each fire period covers one step
of time (a minute by default). The weather row of hour *k* applies from minute 60·*k* to
minute 60·(*k*+1). A message records the minute when the cell caught fire.

In C2F-W the clock is one step behind the fire:

- The ignition period (period 0) already spreads the fire, but does not count as time
  passing. A fire that arrives after 4 minutes of spread is written as "period 3".
- The weather changes one period late: the first weather row lasts 61 minutes, and every
  later change comes a minute after it should.

This goes back to the first Python prototype of Cell2Fire (2019). Its code treats period 0
as the ignition and period 1 as the first period of spread, and the weather update is
written for that. But the code also spreads during period 0, which adds an extra step.
The original C++ has the fix right after ignition, commented out:
`//this->fire_period[year - 1] += 1;   // DEBUGGING!!!`. Back then the default fire period
was 60 minutes, so the weather was a whole hour late. C2F-W changed the default to
1 minute, which made the error small and easy to miss.

There is no computational reason for this behaviour, so we use plain time instead.

Validation: tests convert C2F-W's period *p* into minute *p*+1. The `sb-asc` weather never
changes, so the weather timing makes no difference there. For reference data with changing
weather, the test will expand the weather into one row per minute following C2F-W's
timing, and run c2f-rs with a 1-minute weather period. The workaround stays in the test.

### Values are not rounded inside the model

C2F-W rounds up to two decimals every value that ends up in an output file: rates of
spread, intensities and flame lengths. It does it where the values are computed, so the
rounded numbers are also the ones the model works with. This has been there since the
first C2F-W version, without a comment or a citation. It looks like a way of presenting
outputs with two decimals.

c2f-rs keeps full precision. Rounding, if any, belongs where outputs are written.

Validation: the tests allow for C2F-W's rounding (up to 0.01).

### A message means the fire spread

When the fire reaches the centre of a neighbour that cannot ignite (its fire would be too
weak, for example wet fuel or no wind), the neighbour stays unburnt and the burning cell
keeps pushing at it every period, in case conditions change. Both C2F-W and c2f-rs do this.

C2F-W also writes a message for every one of those attempts, so a single neighbour can
get hundreds of identical lines. c2f-rs writes a message only when the fire actually sets
the neighbour on fire, at that time.

We checked that this repetition was not intended:

- The retrying is intended, and kept. The repeated lines are not: the 2019 Python
  prototype stored messages in a dictionary keyed by (from cell, to cell), so a repeated
  attempt overwrote the previous one. The duplicates appeared when the C++ translation
  stored them in a plain list.
- Nothing in C2F-W reads the messages back. They only go to the output file.
- The tools that read that file assume every message is a fire that spread. The fire2a
  downstream protection value builds a "who burnt whom" graph from it, and the hands-on
  notebook draws arrival time maps from it. Both show a cell that never caught fire as
  burnt.

C2F-W also writes intensity, flame length and rate of spread values in its output grids
for those reached but unburnt cells. Our outputs do not (see below).

Validation: in `sb-asc` every cell reached catches fire straight away, so the reference
messages are unchanged. A unit test covers a cell that only ignites once the wind rises.

### Fewer, self-describing output files

C2F-W writes many folders (`Grids/`, `Messages/`, `SurfaceIntensity/`, ...) with numbered
files, and its burn grids are plain tables of 0s and 1s without map coordinates. c2f-rs
writes four files into one folder:

- `messages.csv`: every spread, with a header: `from,to,time_minutes,rate_of_spread`.
- `arrival_time.asc`: the minute each cell caught fire. Its burnt cells are the burn scar,
  so a separate burn grid is not needed.
- `intensity.asc` and `flame_length.asc`.

The maps are in ESRI ASCII format with the landscape's map coordinates, and get a copy of
`fuels.prj` when the instance has one, so GIS tools place them on the landscape.
Unburnt cells have no data instead of 0. Cells are numbered from 1, as in C2F-W.

A cell's intensity and flame length are those of its fire when it caught fire. C2F-W
writes them every time a message is sent, so the last message decides the value, which
depends on the order of its hash maps when the weather changes. For the same reason we
write no rate of spread map: a cell spreads at a different rate in every direction, and
C2F-W's map just keeps whichever direction was written last. The rates are in the
messages instead.

## C2F-W quirks still reproduced

These are reproduced for now. Each one will either become a difference above, or stay
because it is part of the model.

- The Scott & Burgan length-to-breadth ratio is Anderson's (1983) formula raised to the
  power 0.45. The exponent is not in Anderson's paper, nor in the Scott & Burgan paper
  (González-Olabarria et al. 2023, equation 2), and has been in the code without a comment
  since its first version (C2FSB, 2022). It makes fires much rounder: at 30 km/h the ratio
  is 2.5 instead of 7.7. It most likely compensates for using wind measured 10 m above the
  ground, while Anderson's formula expects the weaker wind at flame height. It is part of
  how this fire model behaves, so we keep it. A later option is to scale the wind down to
  flame height explicitly and use Anderson's formula unchanged.

Known issues, not reached yet:

- The slope effect looks about 100 times too weak: slope is used as a fraction where the
  coefficients look like they expect a percentage. Kitral has the same issue.
- The S&B and Portugal slope effect uses the cell side for diagonal neighbours too.
- Kitral: intensity and flame length of the cells reached by fire are always 0.
- FBP: the ellipse is built differently than in the other models, so the head fire can
  spread close to twice the computed head rate. Flame length is never computed.
- Portugal: the crown fire rate adds `CBDFactor * CBDFactor` instead of `CBDFactor * cbd`.
- Off-by-one index when storing the surface fraction burnt (FBP).
- Crown fire state (`activeCrown`) is a single flag for the whole simulation, not per cell.
- Slope, aspect and elevation are also read as whole numbers in some C2F-W code paths
  (same origin as above). We will keep their decimals when we add slope.
